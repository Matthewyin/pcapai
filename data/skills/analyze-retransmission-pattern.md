# 分析 TCP 重传退避模式

## 适用场景
当观察到 TCP 重传时，通过统计重传包的时间间隔，判断是否为 RFC 6298 定义的标准 RTO 指数退避模式，从而区分"对端无响应"（RTO 退避）与"网络丢包"（快速重传）。

## 执行步骤

1. **取重传包**：用 `list_tcp_retransmissions` 取出会话的所有重传包，按时间排序。

2. **统计间隔**：计算相邻重传包的时间差（ms）。典型 RTO 退避模式：
   - 第 1 次重传：~200ms
   - 第 2 次：~400ms
   - 第 3 次：~800ms
   - 第 4 次：~1600ms
   - 呈 2 倍增长

3. **区分两种模式**：
   - **指数退避**（间隔翻倍）：对端完全无响应，触发 RTO。根因在对端或中间网络（对端宕机/防火墙静默丢弃/路由黑洞）。
   - **快速重传**（间隔短，几 ms 内，由 dup ACK 触发）：网络选择性丢包，对端在响应但部分包丢失。

4. **验证对端状态**：
   - 若是指数退避，检查对端是否有任何反向包（ACK/数据）。完全无反向 → 对端宕机或被丢弃。
   - 用 `get_packet_detail` 看重传包是否带新数据还是纯重传。

5. **对照 RFC**：用 `get_rfc_section(6298, "2")` 回读 RTO 计算与退避规则原文。

## 判定标准

| 重传模式 | 间隔特征 | 根因方向 | RFC |
|---|---|---|---|
| RTO 指数退避 | 翻倍增长（200→400→800） | 对端无响应 | RFC 6298§2 |
| 快速重传 | 短间隔，dup ACK 触发 | 网络丢包 | RFC 5681 |
| 混合 | 两者都有 | 丢包 + 部分超时 | RFC 9293 |

## 注意

- RTO 初始值随 RTT 估算变化，200ms 是典型值不是绝对值。关键是看"是否翻倍"。
- 指数退避通常在几次后放弃（默认 ~15 次或几十秒），之后会发 RST 或静默放弃。
- 必须用 `get_rfc_section` 回读原文后再引用 RFC。
